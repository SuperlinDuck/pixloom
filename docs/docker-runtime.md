# Docker 执行环境（v0.3）

执行环境现已接入统一的 React 多文件工作空间与版本流程；容器是可重建的执行副本，权威源码和不可变预览资源保存在 SQLite。

## 使用

安装并启动 Docker Desktop，运行：

```sh
pnpm sandbox:doctor
pnpm sandbox:prepare
pnpm dev
```

固定镜像更新为 `pixloom-runtime:react-v2`。已有旧镜像的本机需要再次 prepare；该命令不删除旧镜像或用户容器。构建上下文仅限 `sandbox/`，不读取平台 `.env.local`。

创建项目自动排队模板构建；源码页保存草稿、构建并保存版本。环境页可启动、停止和移除容器，操作进入统一项目任务队列。停止和移除保留数据库源码及预览。Docker 不可用时仍可浏览/保存源码、查看历史与已存预览；恢复有原始构建产物的版本可以直接复用。

## 接口与约束

`ProjectRuntime` 提供创建、启动、停止、移除、文件读写/搜索、完整替换文件、固定构建、产物导出、日志和镜像摘要。保留容器内部预览方法供低层验证脚本使用，产品预览不再读取它。

完整装载快照前清理 `src`、`index.html`、旧 `dist` 和构建缓存，防止已删除或恢复前的文件残留。镜像中的固定依赖、构建配置和控制程序保持只读。恢复复用预览时不要求立刻重建容器；下一任务完整装载恢复后的权威快照。

- 容器以 `1000:1000` 用户运行，只读根文件系统、丢弃 capabilities、禁止提权。
- 无网络、无宿主目录挂载、不发布端口、不暴露模型凭证或 Docker Socket。
- 1 CPU、512 MiB 内存、无额外 swap、128 进程上限。
- `/workspace` 64 MiB tmpfs，`/tmp` 16 MiB tmpfs，有限轮转日志。
- 固定 Vite 构建最多 90 秒，操作总时限 150 秒。取消中止操作并尝试停止容器。
- 仅允许 `index.html` 和 `src/` 白名单文本文件；单文件 128 KiB、最多 64 文件、源码合计 1 MiB，拒绝路径穿越、隐藏路径、符号链接和文件/目录冲突。
- 产物单资源最多 2 MiB、最多 128 资源、合计 8 MiB；仅固定控制程序导出，平台再次验证。
- 默认最多三个环境，容量满时优先移除最旧空闲环境。Worker 每三十秒扫描，空闲五分钟后移除，可通过 PIXLOOM_MAX_RUNTIME_CONTAINERS / PIXLOOM_RUNTIME_IDLE_SECONDS 调整。新容器带实例标签，不回收其他数据目录的环境。

固定模板依赖只在 prepare 时通过锁文件安装，运行期间不安装任意 npm 依赖。执行代码仍是本机受控原型，不是面向陌生用户的完整公共执行平台。

## 持久预览

```text
sandbox iframe → /api/previews/<artifactId>/index.html
               → SQLite 中的构建资源
```

产物 URL 不随当前版本切换而覆盖，构建与版本同事务提交。失败、取消或停止容器不会使上一可用预览失效。同项目相同文件 hash 和镜像摘要可复用产物；手工重建某版本预览不产生源码版本，要求模板摘要匹配。

资源响应包含 CSP sandbox，iframe 仅允许脚本，不允许同源、外部网络、表单、弹窗或宿主页面访问。ES Modules 需要 CORS，网关只为预览 GET 路径放行跨站资源请求，平台 API 仍拒绝跨站请求。

尚未实现开发服务器、WebSocket、HMR 或独立预览域；此阶段使用构建产物预览。

## 验证

```sh
pnpm sandbox:verify
pnpm workspace:verify
```

前者验证容器隔离、源码读写、构建、资源读取、构建失败和重启源码恢复。后者使用临时数据库及新测试容器，验证 v1/v2、失败不覆盖、持久资源路径、恢复 v3、继续 v4、快照外文件清理、移除容器后预览资源保留。两者均清理自己创建的容器；后者也清理临时数据库。

2026-10-24 已在本机 Docker Engine 29.9.2 上通过新的工作空间版本闭环验证。浏览器验证记录见任务交付说明。

登录模式下预览要求项目所有者授权或十五分钟资源凭证；可信外层续期，退出或账号失效立即阻止资源请求。已有预览不依赖容器。详见 [VPS 部署](vps-deployment.md)。

## 排查与修正

首次调用在生成源码时遇到 `MAX_TOKENS`；将单次输出上限由 12,000 调整为 24,000，并为 Gemini 3 明确使用较低思考强度，保持任务总预算不变。期间还遇到 HTTP 429，等待后重跑成功；错误处理已补充分钟/秒级限流、每日配额和账户额度不足的分类，不记录上游错误正文。

最初一组生成产物虽然构建成功，但浏览器中依赖 `form onSubmit` 的新增操作被 sandbox 阻止。补充生成指令：应用操作使用 `type="button"` / `onClick` 与显式 Enter 事件，存储读写需要异常回退。随后重新执行完整两轮真实生成，再完成上述交互验收；未放宽 sandbox 或 CSP。

## 2026-10-26 生成等待优化

首次生成先完成页面、样式和数据库定义，再验证。工具层会推迟尚未修改页面的 schema 中间构建，不计构建失败；后端结构直接读取定义文件。推荐直接调用 `browser_test`，一次完成必要的构建、页面加载检查和核心行为验证；显式 `build` 对未变化的成功候选复用结果。

加载检查通过后，立即持久化私有候选预览并在工作台显示“候选预览 / 正在检查功能”，无需等待后续行为步骤和模型总结。候选产物沿用项目所有者及预览凭证授权，独立于草稿、版本和发布站点；不参与正式构建缓存。替换、取消、失败和 Worker 恢复清理候选产物及凭证；最终提交直接沿用相同产物，保存正式版本。未通过加载检查的产物不会提前展示。

同一源码的一轮功能测试成功后，后续 `browser_test` 返回已执行步骤和明确的跳过说明，不运行新步骤；源码修改后才能重新验证。模型指令要求一次规划核心测试，通过后及时总结。所有浏览器检查共用持久化的累计 90 秒时间预算，单次仍受普通应用 25 秒 / Cloud 应用 60 秒限制。超时、失败和环境不可用继续作为告警，不阻塞成功构建的版本保存，不可声称未执行的步骤通过。

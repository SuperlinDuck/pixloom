# 多文件工作空间与版本实施方案

日期：2026-10-24。对应 [路线图第 2 阶段](roadmap.md)。状态：第 2 阶段已实现；当前使用手工编辑验证闭环，Coding Agent 待第 3 阶段接入。

## 目标与取舍

下一版统一使用固定 React/Vite 多文件项目，移除单文件 HTML 生成、存储和预览路径，不兼容 v0.2 数据和接口。不再维护“聊天应用”和“Docker 实验环境”两套代码状态。

本阶段交付：创建模板项目、编辑多个文件、保存草稿、构建并保存版本、查看文件差异、恢复旧版，以及中断后恢复。先通过手工修改和受控任务验证版本闭环；真实 AI 生成改为第 3 阶段的 Coding Agent 工具循环，不能继续把旧 HTML 生成按钮接到新项目上。

采用线性版本历史和单工作草稿。GitHub 同步、多分支、PR、Remix、发布环境、数据库回滚、HMR、浏览器行为验证均不进入本阶段。`index.html` 仍是 Vite 项目入口，移除的是单文件 HTML 产品模式。

## 一、用户操作与状态语义

明确三个概念：

- **草稿**：可修改、可暂时构建失败，保存后可在重启时找回。
- **当前版本**：最近一次被用户采用、且通过构建验证的不可变快照，是后续任务的默认基线。
- **查看的版本**：仅前端选择的历史记录，查看源码、差异不会改变当前版本或后续任务基线。

创建项目时持久化模板草稿，排队执行初始化构建。构建成功形成 v1；Docker 不可用时仍可读写草稿，界面显示“尚无可用版本”。

手工编辑流程：修改文件 → 保存草稿 → 点击“构建并保存版本” → 成功形成 v2。保存草稿不产生版本；失败保留草稿、错误日志和 v1。无文件变化时不创建空版本。

草稿存在未提交修改时，提交 AI 任务前必须明确选择先构建保存或丢弃草稿；不静默忽略手工修改，也不把未经验证的草稿当作当前版本。第 3 阶段沿用这一规则。

恢复流程：查看 v1 → 点击“恢复为当前版本” → 展示被替换的草稿及文件变更 → 确认 → 构建目标快照或复用已验证产物 → 形成 v3。v3 文件与 v1 相同，记录 `restoredFromVersionId=v1`，v2 不删除。若有已保存草稿，恢复前保留一份恢复备份；浏览器尚未保存的编辑也必须提示处理。

v3 的下一次修改基于 v3；v3 的 `parentVersionId` 指向恢复前的当前版本 v2。这样时间顺序、操作原因和恢复来源都可追溯。

## 二、数据模型

继续使用 SQLite。首版将文件清单和完整文本放入快照 JSON，在现有 1 MiB 源码上限下优先保证事务简单；不先引入 Git、对象存储或文件级内容寻址。

| 表                   | 关键字段与职责                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `projects`           | `id/name/currentVersionId/createdAt/updatedAt`；当前指针允许为空                                                                                    |
| `workspace_drafts`   | `projectId/baseVersionId/revision/files/hash/updatedAt`；唯一的持久工作草稿                                                                         |
| `versions`           | `id/projectId/number/parentVersionId/restoredFromVersionId/source/taskId/summary/files/hash/templateId/artifactId/createdAt`；只保存验证成功的版本  |
| `tasks`              | 统一的项目操作记录：`kind/status/baseVersionId/expectedDraftRevision/attemptId/candidateFiles/resultVersionId/events/error`；后续可接模型配置、用量 |
| `preview_artifacts`  | `id/projectId/sourceHash/templateId/createdAt`；不可变构建产物的清单和受限二进制资源                                                                |
| `runtime_workspaces` | 容器标识、运行状态、当前加载的候选源码 hash、模板标识；不再保存第二份权威源码                                                                       |
| `draft_backups`      | 恢复操作覆盖草稿前的文件、基线和 revision，支持找回                                                                                                 |

`source` 使用 `template/manual/agent/restore`。`tasks.kind` 覆盖 `initialize/commit/restore/agent/preview` 及容器生命周期操作，使用同一项目互斥入口；替换当前分开的 `tasks` 与 `runtime_jobs` 排队逻辑。

快照按规范化路径排序，用路径与原始内容计算稳定 hash；不自动修改文件换行。文件差异由两个完整快照计算，不依赖连续补丁回放。`templateId` 对应固定依赖、构建配置和镜像摘要，避免同一标签更新后把不同环境误认为相同构建。

版本号在提交事务内按项目递增，`taskId` 对结果版本加唯一约束。项目详情只返回版本摘要，文件正文按草稿或版本单独读取，避免轮询反复传输全部历史源码。

## 三、任务与提交协议

所有修改代码、切换当前版本和操作同一容器的任务统一串行；同项目最多一个 queued/running 操作。数据库建立部分唯一索引，API 内不只依赖 UI 禁用按钮。草稿修改携带 `expectedRevision`；有活跃构建或恢复任务时拒绝写草稿并返回 409。

任务链路：

```text
捕获基线与草稿 revision
  → 固化候选文件与 attemptId
  → 校验路径、必需文件、大小
  → 完整装载候选源码
  → 固定 Vite build
  → 导出受限构建产物
  → 事务校验提交条件
  → 保存版本与产物、切换当前指针、更新草稿基线、完成任务
```

候选文件在任务入队时固化，执行时不重新读取“最新草稿”替代。未来 Agent 在任务自己的候选文件集中编辑，工具步骤不会直接写入当前版本。

提交事务必须同时满足：任务仍 running、`attemptId` 仍有效、项目当前版本仍等于 `baseVersionId`、草稿 revision 未变化。版本插入、产物保存、项目指针、草稿更新和任务完成必须同一事务提交；Docker、模型调用、构建与文件传输均在事务外执行。

取消先持久化任务终态，使本次 attempt 失效，再中止进程。迟到构建和模型结果不得提交；旧 attempt 的清理也不能停止新 attempt 的容器或修改其状态。新任务须等旧执行退出或接管流程确认清理后才能操作该容器。

这是本机单 Worker 下的操作互斥和过期结果保护；不把它宣称为多 Worker 分布式调度。未来引入并发 Worker 时另做执行资源 fencing。

## 四、预览必须绑定不可变产物

推荐本阶段增加小规模构建产物持久化，预览从 SQLite 中读取产物，不再依赖容器内可覆盖的 `/workspace/dist`。

原因：若继续原地构建并直接读取 `dist`，失败构建、删除文件和容器重启都可能使上一版本失去预览；仅新增 `versionId` 字段不能解决产物被覆盖的问题。

具体做法：

1. 固定控制程序导出构建后的 `dist`；禁止符号链接、特殊文件、路径穿越和无界输出。建议单资源 2 MiB、总产物 8 MiB、最多 128 个资源，作为首版可调整限制。
2. 构建前生成 `artifactId`，以不可变产物 URL 作为 Vite base。当前项目令牌不再作为会覆盖内容的预览地址。
3. 版本绑定 `artifactId`；iframe 地址使用 `/api/previews/:artifactId/index.html`。沿用现有 CSP、sandbox、内容类型和本机访问限制。
4. 候选构建失败、取消、停止或移除容器时，当前版本的已保存预览继续可访问。
5. 查看历史时先显示历史源码和差异；有产物直接预览，没有则明确提供“构建此版本预览”，使用同一项目操作锁。历史预览构建不切换当前版本，不新增源码版本。
6. 同项目、同源码 hash、同模板镜像摘要的产物可复用。只在数据库提交时保存新产物，提交失败不留下被版本引用的半成品。

源码与版本是事实来源，产物是可重建缓存。首版设置项目存储预算和明确的超限错误，不自动删源码历史；后续可清理未被当前版本引用的历史产物，并保留按需重建入口。预览 ID 只定位本机资源，不替代未来的用户授权。

## 五、文件操作与差异

沿用 `sandbox/file-tools.cjs` 的白名单：`index.html`、`src/` 下允许的文本源码；单文件 128 KiB、最多 64 个文件、合计 1 MiB。首版保留 JSX/JS，不在此阶段顺带加入 TypeScript 与任意依赖。

- 支持批量新增、修改、删除、重命名；重命名存储为一次原子“删旧文件 + 写新文件”。文件夹由路径推导。
- 路径先校验再使用，不把 `../` 归一化后放行；拒绝绝对路径、反斜杠、空段、隐藏路径、重复路径及文件/目录冲突。
- `index.html`、`src/main.jsx` 是固定入口，首版禁止删除；其他依赖和引用问题由构建报告。
- 手工编辑保存前、任务入队前、容器控制程序内均校验完整候选集合；配额按 UTF-8 字节计算。
- 完整装载快照时清理旧源码和旧 `dist`，防止恢复后残留“未来文件”；固定只读依赖和控制程序不得被清理或覆盖。
- 文件树与历史源码从数据库读取，Docker 离线也能浏览和编辑；容器中的文件只作为执行副本。
- 差异支持 added/modified/deleted 和逐行对比；默认对比选中版本与其父版本，可选择与当前版本对比。重命名首版按删除加新增展示。

## 六、界面与接口

主工作台保留左侧项目、聊天区域，右侧统一为“预览 / 源码 / 差异”，历史从统一入口打开。环境面板只显示 Docker、镜像、日志和生命周期操作。

源码区为文件树 + 编辑器 + 草稿状态。明确标出“未保存到草稿”“草稿已保存，尚未构建”“当前 vN”“正在查看历史 vM”。轮询不能覆盖本地未保存文本；保存冲突提示重新载入。切换历史和项目时处理未保存编辑。

历史条目显示版本号、摘要、时间、来源、当前标记；恢复版本显示来源版本。收藏、版本改名、截图缩略图可在基本闭环之后补充。没有 AI 工具循环前，聊天区域明确显示尚未接入，提供模板和手工编辑入口。

| 方法与路径                                         | 用途                                             |
| -------------------------------------------------- | ------------------------------------------------ |
| `POST /api/projects`                               | 创建 React 项目及模板草稿，尝试排队初始化构建    |
| `GET /api/projects/:id`                            | 项目、任务摘要、当前版本与草稿状态               |
| `GET /api/projects/:id/files?versionId=...`        | 省略版本时读草稿，否则读不可变版本文件           |
| `PATCH /api/projects/:id/files`                    | `{expectedRevision, operations[]}` 原子修改草稿  |
| `GET /api/projects/:id/versions`                   | 分页历史摘要                                     |
| `GET /api/projects/:id/versions/:versionId`        | 版本详情及文件清单                               |
| `GET /api/projects/:id/diff?from=...&to=...`       | 文件级与行级差异，支持草稿与版本比较             |
| `POST /api/projects/:id/commits`                   | 固化草稿并排队构建、保存版本；返回 202 和任务 ID |
| `POST /api/projects/:id/restores`                  | 指定目标与预期当前状态，排队恢复；返回 202       |
| `POST /api/projects/:id/previews`                  | 历史版本产物缺失时排队重建预览                   |
| `GET /api/tasks/:id`、`POST /api/tasks/:id/cancel` | 查询与取消统一操作                               |
| `GET /api/previews/:artifactId/...`                | 从持久产物读取预览资源                           |

读取版本、差异和产物均校验项目归属；不要把数据库中存在某个 ID 当作归属检查。写请求冲突返回 409；配额超限返回 413；路径等输入错误返回 400。控制类环境操作沿用入口，但进入统一任务表。

## 七、重启、故障与数据切换

重启后，queued 任务保留。原 running 的构建/恢复任务使旧 attempt 失效，以新 attempt 从已持久化的候选快照重新执行；不信任容器残留文件或 `built=true`。已提交任务通过 `resultVersionId` 和唯一约束直接认定完成，不重复生成版本。

未来 Agent 的模型调用不能在版本阶段假定可无成本重放；其调用记录、工具检查点和费用提示在第 3 阶段设计。现阶段没有新 HTML 调用任务。

Docker 不可用时不切换当前版本，保留待构建草稿与可用历史产物。恢复目标缺少产物且无法构建时报告失败；不能先切换代码后声称恢复成功。产物损坏时明确标记预览不可用，允许重建。

按用户决定，不迁移旧 HTML 数据。新结构使用新的 schema 版本和独立数据库文件，例如 `.pixloom/pixloom-v3.db`；新程序默认进入新数据库，旧 `pixloom.db` 保留且不自动删除。Web、Worker 和脚本统一使用同一个数据库解析函数。遇到不匹配的 schema 明确报错，不对旧表执行有歧义的部分升级。

移除旧 HTML schema、模型输出协议、静态 HTML 验证器、`srcDoc` 预览、HTML 导出与示例入口。模型供应商请求适配器可保留其基础网络逻辑供第 3 阶段重用。React 模板作为新的非 AI 示例。旧测试按新行为重写，不保留旧模式兼容断言。

## 八、实施顺序与验收

### 2.1 存储与操作协议

建立新 schema、草稿/快照/hash/diff；统一任务互斥、基线和 attempt 校验。先用模拟 Runtime 验证成功提交、失败不提交、过期结果拒绝和重复执行幂等。

### 2.2 构建与持久预览

实现完整装载、旧文件删除、受限产物导出、不可变预览路由和恢复任务。Docker 实机验证容器停止后旧版预览仍可访问，恢复后新增文件不会残留。

### 2.3 统一工作台与旧路径移除

接入文件树、批量草稿编辑、行级差异、版本历史、恢复与重试；移除 HTML 路径和双源码状态。同步 README、架构、运行环境说明。业务接入完整后运行类型检查、测试、生产构建和容器验证。

完成标准：

1. 创建模板得到 v1；同时修改组件、样式并新增文件，构建得到 v2，差异正确。
2. 保存语法错误的草稿后构建失败，v2 源码和预览仍可用；刷新仍保留失败草稿。
3. 恢复 v1 得到 v3，文件集合与 v1 完全一致，v2 新增文件不残留，旧版本均保留。
4. 从 v3 再修改得到 v4，基线确认为 v3；未来 Agent 使用同一基线接口。
5. 取消、连续重复请求、两个浏览器页写入、Worker 中断后重跑，不产生重复版本或迟到覆盖。
6. 查看 v1 的源码、差异或预览不改变当前 v4；Docker 停止后源码和已有预览仍可查看。
7. 路径穿越、符号链接、超大文件、总量超限、跨项目版本引用、产物资源越界均被拒绝。
8. 工作台没有仍可调用的单文件 HTML 生成入口；本阶段不把构建通过表述为浏览器行为验证通过。

第 2 阶段完成后，第 3 阶段只需接入“读取基线 → 编辑候选文件 → 调用受限构建 → 提交版本”的工具循环，不再重新设计源码与版本模型。

## 实现补充

当前预览产物持久化在 SQLite。恢复复用原产物时立即恢复数据库中的权威源码与预览，容器文件作为执行缓存，在下一次启动或构建时完整装载。显式重建预览仅更新缓存引用，源码快照和版本编号不变；模板摘要不匹配时拒绝用新模板重建历史预览。项目源码与构建资源预算为 128 MiB。

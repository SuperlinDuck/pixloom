# Pixloom 下一步实施计划

更新日期：2026-10-24。

研究上下文见 [Atoms 调研](atoms-research.md)，当前实现边界见 [架构说明](architecture.md)。

## 历史基线：v0.2 本地原型

- 单用户项目工作台、独立 Worker、SQLite 任务与版本持久化。
- Gemini Developer / Vertex Express 与 GPT Responses 适配器。
- 自包含 HTML 应用生成、静态检查、一次修复、隔离预览、导出和版本恢复。
- 已使用本地配置的 Gemini 3.5 Flash 实际生成计数器，验证加一按钮可操作。默认模型示例已统一为 Gemini 3.5 Flash，并保留环境变量覆盖。
- Gemini 完成过真实调用验证；GPT 目前通过模拟响应的适配器测试，尚未做真实调用验证。
- 密钥与本地项目数据不进入 Git。本阶段不开放公网访问。

## 下一里程碑：v0.3 React 项目生成与运行

目标：统一为可持续修改的 React/Vite 多文件项目，移除旧单文件 HTML 模式；不兼容 v0.2 数据和接口，旧数据库保留备份。

### 1. 执行环境基础（已实现并完成本机容器验证）

- 确认本机 Docker 环境可用；定义 Runtime 接口：创建环境、读写与搜索文件、运行受限命令、读取日志、启动预览、停止与清理环境。
- 实现 Docker 适配器，固定首个 React/Vite 模板及依赖，暂不支持任意技术栈。
- 为容器设置 CPU、内存、进程数及任务时间限制，使用非 root 用户；不向项目容器暴露宿主密钥或 Docker Socket。
- 将平台控制状态、模型凭证和项目运行环境分开管理。

验收：不调用模型，也能创建模板、执行构建、打开预览并清理环境；运行失败可以定位日志。

实现与限制见 [Docker 执行环境](docker-runtime.md)。固定模板、源码快照与构建产物预览已接入下述多文件版本流程；模型工具循环已在第 3 阶段接入，开发服务器热更新仍属于后续工作。

### 2. 多文件工作空间与版本（已实现）

实施方案见 [多文件工作空间与版本方案](workspace-versions-plan.md)。已实现模板与手工编辑版本闭环，AI 工具循环已在第 3 阶段接入。

- 将单个 HTML 版本扩展为项目文件清单与快照；支持文件树、源码查看和修改差异。
- 区分可持久化草稿与验证通过的不可变版本；统一项目操作互斥，固定任务基线并拒绝过期结果。
- 限制文件路径与读写范围，阻止路径穿越；限制文件大小与工作空间总大小。
- 任务基于当前版本修改，验证通过后再更新当前版本；失败时保留上一个可用版本。
- 恢复版本时同时恢复文件与运行预览，明确重启后的任务恢复规则。
- 恢复产生新的版本并保留历史；预览绑定持久化构建产物，失败、取消或容器停止时仍可查看上一可用版本。

验收：已通过 Docker 实机验证两个版本构建、失败保留、差异、恢复为新版本、继续修改、旧文件清理，以及移除容器后读取历史预览资源。

当前基线：v0.3 多文件工作空间。旧 HTML 模式已移除，使用独立的 `pixloom-v3.db`；草稿、版本、产物和统一任务均持久化。第 3 阶段工具循环已实现并完成 Gemini 真实验收，第 4 阶段已接入自动浏览器验证与修复，独立源开发预览及 HMR 待完成。

### 3. Coding Agent 工具循环（已实现并完成 Gemini 真实验收）

- 基于多文件候选快照接入读文件、搜索、编辑、运行构建、读取错误并修复的工具循环。
- Gemini 与 GPT 使用统一工具定义、事件格式和任务产物；分别实现模型协议适配。
- 设置最大步骤、输出预算、总时长和修复次数；取消后停止后续操作，避免迟到结果覆盖新状态。
- 增加真实调用配置检查，改善模型不可用、额度不足和网络失败的提示；统一模型配置示例。

实现：已接入候选源码工具、统一 Gemini/GPT 协议、任务入口与 UI、构建修复、持久预算、取消和重启保护。失败候选可载入编辑器继续修改；配置检查与可选真实连通探测见 README。

验证：协议与流程回归测试、类型检查、生产构建，以及本地模型夹具驱动的真实 Docker 两轮构建通过。新增 `pnpm agent:verify` 默认不调用模型；`pnpm agent:verify --live --provider=gemini` 执行真实模型验收并可能产生费用。2026-10-24 经授权完成 Gemini 3.5 Flash 两轮真实工具调用与 Docker 构建：待办应用 5 步，分类筛选增量修改 9 步，两轮均无失败构建。GPT 仍仅通过模拟协议测试。

验收：真实模型下创建待办应用，再增加分类筛选；使用正式预览相同的 sandbox/CSP，通过浏览器实测新增、勾选完成、删除，以及全部/工作/生活筛选，未出现控制台错误。检查时发现并修正了原生表单提交与 sandbox 的冲突，生成指令现要求使用显式点击事件。预览存储仍回退内存，不保证刷新后持久化。完整记录见 [Coding Agent 验证](coding-agent-verification.md)。浏览器行为自动验证在第 4 阶段接入。

### 4. 预览与行为验证（自动验证已接入，开发预览待实现）

- 增加容器预览路由与生命周期管理，支持开发服务器连接及必要的热更新通道。
- 将生成应用与工作台放在不同源，限制项目之间及项目对平台的访问。
- 已实现：每次 AI 候选构建后以相同 sandbox/CSP 运行 Chromium 加载检查，收集页面异常和控制台错误；Agent 使用受限 `browser_test` 执行交互与断言，失败反馈修复，验证通过前不保存版本。浏览器失败次数持久化、最多三次，取消后禁止迟到提交；每次修改源码后重新验证。手工构建仍仅验证编译。
- 已增加生成、构建、验证、保存阶段及行为步骤日志；连接恢复与完整中断体验仍待完善。

验收：新建、生成、预览交互、继续修改、版本恢复这一完整流程通过；容器或 Worker 中断后能够明确恢复或报告失败。

## 后续里程碑

1. **公开测试准备**：认证、项目归属与授权、模型用量额度、磁盘配额、审计、备份和预览访问控制。公开部署前完成此阶段。
2. **可靠调度与扩展**：根据实际并发需要引入 PostgreSQL、任务队列、任务租约与 fencing，验证重试幂等性和恢复行为。
3. **多 Agent 协作**：规划者、产品和架构角色按复杂度加入；持久化 PRD 与方案，增加方案审批和结构化交接。
4. **全栈与正式发布**：逐步增加数据库、认证、存储集成，再实现生成应用的持久部署、自定义域名和独立配置。

先交付 v0.3 的完整项目生成闭环，再扩展角色数量、模型竞赛和增长工具。每阶段以可运行的验收场景作为完成标准。

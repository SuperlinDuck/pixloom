# Pixloom 交付链路

更新日期：2026-10-25。

交付以已保存的版本为单位。工作草稿、候选源码、可预览版本、交付包和线上发布各有独立语义。

## 当前链路

```mermaid
flowchart LR
  A[用户需求 / 手动修改] --> B[候选源码 / 草稿]
  B --> C[Docker 固定模板构建]
  C --> D{验证}
  D -->|失败| B
  D -->|通过| E[不可变源码版本 + 构建产物]
  E --> F[工作台版本预览]
  E --> G[按版本导出 ZIP 交付包]
  G --> H[外部静态服务器 / 继续开发]
```

AI 任务必须通过构建、页面加载检查和当前候选源码的行为断言；失败反馈给模型修复。手工构建只检查编译。恢复复用历史产物，不自动补测。导出沿用版本原有验证边界，不把手工版本标记为完成浏览器验收。

失败或取消不会替换上一可用版本。恢复历史创建新版本；导出历史不会切换当前版本，也不会覆盖草稿。

## 本阶段：版本交付包（已实现）

工作台右上角的下载按钮导出正在查看的版本：默认是当前版本，进入历史后导出所选历史版本。按钮提示明确版本号；存在未保存或未构建草稿时，交付包仍只包含版本快照。首次构建前不可导出。

接口：`GET /api/projects/:id/versions/:versionId/export`，返回 ZIP 附件；项目和版本必须匹配。沿用本机 Host 和跨站请求限制，不提供公网分享链接。

```text
pixloom-<projectId>-v<number>.zip
├── manifest.json                  来源、版本及各文件 SHA-256
├── README.md                      运行、重建及发布边界
├── source/
│   ├── index.html、src/...         所选版本的原始源码
│   ├── package.json               固定模板依赖，补齐 dev/build/preview
│   ├── package-lock.json          当前平台随附的模板锁文件
│   └── vite.config.mjs            独立构建配置，base 为 ./
└── site/
    ├── index.html                 原版本入口副本
    └── api/previews/<artifactId>/  原始产物，内容逐字节保留
```

`site/` 可作为独立站点根目录直接提供静态服务，不需要 Pixloom、模型、Worker、Docker 或 npm 安装。保留原始 Vite base 对应的静态目录，避免替换 JS/CSS 内容、破坏动态 import 或二进制资源；该目录名称不是对平台 API 的依赖。原始 `site/` 产物不支持直接挂在 URL 子目录下，子目录部署需从源码配置 base 后重建。

`source/` 使用当前平台附带的固定模板依赖和可移植配置，执行 `npm ci && npm run build` 可重建；它并非原 Docker 镜像的归档，不承诺逐字节复现原产物。原始镜像标识及源码 hash 保存在清单中，原构建快照保存在 `site/`。导出不会安装依赖或执行项目源码。

版本与产物在一个同步事务中读取，校验项目、源码 hash 和模板标识；即使导出期间发生预览重建，包内清单与资源仍来自同一份快照。导出为只读操作，不新增版本、任务或持久副本，不要求 Worker/容器在线。

仅按白名单打包版本源码、固定模板文件与对应产物，不读取 `.env`、宿主目录、其他项目或任务对话。清单列出除自身外的全部文件 hash。归档采用有界 ZIP32 STORE 格式，最多 256 文件、文件内容合计 12 MiB；现有源码与构建产物限制继续生效。

独立托管不会自动继承平台预览的 sandbox/CSP；正式上线需审核应用并配置站点策略。Cloud 版本额外包含公开连接配置与后端定义，仍连接原有开发资源，不复制数据库、用户或文件，也不自动创建其他后端或迁移数据。导出不包含应用数据备份，不等于公网发布。

## 自动发布（已实现）

已接入固定版本发布、发布记录、独立网关、Caddy 按项目域名授权证书、更新、失败保留、回滚及下线。线上指针在 SQLite 事务中切换，旧资源持续可读；回滚不覆盖草稿或切换开发版本。已有本机单账号登录，公网多用户授权仍待实现，当前控制面保持本机/SSH 隧道。完整配置与边界见 [自动发布](publishing.md)。

## 后续交付阶段

1. **开发预览**：独立预览源、草稿与稳定版本预览分离、HMR、连接与容器恢复。保持现有持久版本预览可用。
2. **发布基础**：认证与项目授权、配额、发布操作审计、备份恢复、预览与发布访问控制。
3. **静态发布扩展**：单机版本发布、状态、稳定地址、失败保留、回滚和下线已实现；后续增加公网控制面授权、自定义域名与 GitHub 同步。
4. **全栈交付**：应用后端、按项目隔离的数据库账号、上传文件、运行配置及数据库迁移。数据库部署独立于临时构建沙箱；应用代码回滚与数据迁移回滚分别设计。

当前可独立公开发布站点；平台控制面开放前仍需认证授权，保持本机单用户访问。

## 验证

- `pnpm test`：ZIP 路径/容量边界、版本与产物一致性、历史导出、草稿隔离、跨项目拒绝、清单与二进制完整性及 API 附件。
- `pnpm delivery:verify`：临时数据库 + Docker 构建，移除容器后导出，Python 标准 ZIP 阅读器校验并解包，以独立静态服务器运行产物，Chromium 访问及交互验证。需要 Python 3 与已安装的 Chromium/Chrome；不使用模型或现有项目。

2026-10-24 本机验收通过：回归与类型检查、独立目录生产构建、标准 ZIP 解包与逐文件 hash、真实 Docker 产物的独立静态服务、动态模块及图片加载、加减交互。另在隔离生产服务中实际下载当前/历史版本，验证草稿隔离、当前版本指针不变，以及 360px 窄屏下载与工具栏布局。
